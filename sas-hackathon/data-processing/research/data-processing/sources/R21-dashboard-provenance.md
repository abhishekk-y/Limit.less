# R21 — Dashboard provenance

- **Source:** Jarske et al. (2023), *Modeling the Dashboard Provenance*.
- **Type:** Visualization research paper / provenance model proposal.
- **URL:** https://arxiv.org/abs/2308.06788
- **Credibility / recency / bias:** 3 / 3 / 2. Research proposal and case examples; not a user-outcome evaluation of this product.
- **Relevant short excerpt:** “a clear and precise understanding of the context in which a specific dashboard was developed.”
- **Finding used:** Provenance metadata should travel with dashboard components so users can inspect source and analytical context.
- **Design implication:** Every chart needs dataset, run/version, observation unit, numerator, denominator, transformation, quality state, and limitation. Hover-only metadata is insufficient.
- **Limit:** A provenance UI improves traceability design; it does not establish the underlying data are representative or accurate.
